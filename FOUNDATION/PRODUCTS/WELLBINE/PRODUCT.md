# Wellbine Product

**Version:** 0.1.0

**Status:** Active

**Last Updated:** July 2026

---

# Purpose

This document defines the official product direction of Wellbine.

It explains what Wellbine is, what it is not, how it uses AAI and what principles should guide product decisions.

---

# Product Definition

Wellbine is not just a habit tracker.

Wellbine is not just a health app.

Wellbine is not just an AI assistant.

Wellbine is an Adaptive Human Operating System designed to help users improve health, performance and longevity through intelligent, context-aware guidance.

---

# Core Objective

The objective of Wellbine is to reduce cognitive load and help the user take the right action at the right moment.

Wellbine should not simply display data.

Wellbine should interpret context, anticipate needs and guide the user toward better outcomes.

---

# Relationship With AAI

Wellbine is the first product built using Adaptive Alignment Intelligence (AAI).

AAI provides the intelligence architecture.

Wellbine applies that architecture to:

- Health
- Performance
- Longevity
- Daily behavior
- Biological context
- Preventive routines
- User guidance

---

# Relationship With POPAE

Wellbine uses the POPAE cycle as its adaptive operating logic.

```text
Prepare

↓

Observe

↓

Predict

↓

Align

↓

Evolve
```

In Wellbine:

- Prepare means reducing noise and organizing the user context.
- Observe means collecting behavioral, biological and interaction signals.
- Predict means anticipating what the user may need next.
- Align means guiding the user toward the next best action.
- Evolve means learning from feedback and outcomes.

---

# Relationship With BCAS

Wellbine uses BCAS as its biological context methodology.

BCAS means:

**Biological Context Alignment System**

BCAS replaces rigid clock-based routines with context-aware biological guidance.

The system should not ask only:

**What time is it?**

It should ask:

**What biological context is the user experiencing now?**

---

# Product Philosophy

Wellbine must feel simple, intelligent and useful.

The user should not need to interpret complex dashboards.

The system should guide the user clearly.

The core product experience should answer one question:

**What is the next best action now?**

---

# Push-First Principle

Wellbine should generate value even when the app is closed.

Push notifications are not simple reminders.

They are operational extensions of AAI.

Whenever possible, the user should be able to respond directly through interactive Push without opening the app.

---

# Current Stack

The current Wellbine stack is:

- FlutterFlow for app development
- Supabase for backend, database, authentication and storage
- Firebase Cloud Messaging for Push Notifications

The stack is intentionally simple.

The goal is speed, clarity and practical execution.

# Product Rules

Wellbine should follow these product rules:

- Reduce cognitive load.
- Avoid unnecessary screens.
- Avoid excessive data display.
- Prioritize guidance over information.
- Prioritize context over clock time.
- Prioritize recovery over punishment.
- Prioritize interactive Push over forced app opening.
- Keep the interface calm, premium and direct.
- Make every interaction useful.

---

# What Wellbine Is Not

Wellbine is not a social network.

Wellbine is not a medical diagnosis platform.

Wellbine is not a generic habit checklist.

Wellbine is not a dashboard-first app.

Wellbine is not a notification spam system.

Wellbine is not dependent on the user opening the app every day to create value.

---

# Current Direction

The current product direction is to simplify the app around:

- Biological context
- Next Best Action
- Interactive Push
- Static Orb interface
- Wellbine Daily
- Daily Stack
- Minimal cognitive load
